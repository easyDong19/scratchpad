# 템플릿.md 만들기 (Scratchpad 템플릿 드릴용)

Scratchpad의 **레포에서 가져오기**는 `템플릿.md`를 읽어 템플릿을 만든다. 사용자는 템플릿마다 "보고 따라치기 → 가리고 백지 복원 → 채점"을 목표 시간 안에 2번 연속 성공할 때까지 반복한다. 그래서 이 파일의 목적은 정리가 아니라 **외워서 손으로 칠 코드 조각을 정해 주는 것**이다. 형식이 조금만 어긋나도 앱이 조용히 건너뛰거나 두 템플릿을 합쳐 버리므로, 마지막에 반드시 검사기로 확인한다.

## 1. 먼저 정할 것

요청에 없으면 짧게 묻고, 사용자가 맡기거나 물어볼 수 없는 상황이면 아래 기본값으로 가되 **어떤 값을 골랐는지 끝에 알려 준다.** 사용자가 직접 말한 값은 기본값보다 항상 우선한다.

| 항목 | 기본값 |
|---|---|
| 주제 | (필수) 예: BFS/DFS 그래프 탐색 |
| STAGE 번호 | 사용자가 말한 번호. 없으면 학습 폴더의 기존 `stage*` 폴더 다음 번호 |
| 언어 | C++ |
| 추가 제약 | 레포의 CLAUDE.md나 로드맵에 있으면 따른다 (예: `bits/stdc++.h` 금지, `auto [a, b]` 금지, 함수형 `solution` 제출) |
| 저장 위치 | `<학습 폴더>/stage{번호}-{주제}/템플릿.md`. 학습 폴더 = 다른 `stage*` 폴더들이 모여 있는 곳 (예: `coding-test/`) |

같은 학습 폴더에 다른 `stage*/템플릿.md`가 있으면 하나 열어 보고 말투·주석 밀도·변수명을 맞춘다. 사용자는 여러 STAGE를 같은 손버릇으로 외우기 때문이다.

**같은 번호의 STAGE 폴더가 이미 있으면** (예: `stage6-모의고사/`):
- 그 폴더에 템플릿.md가 없고 주제도 맞으면 그 폴더에 만든다.
- 주제가 다르거나 템플릿.md가 이미 있으면 덮어쓰지 말고, 어떻게 할지 묻는다. 물을 수 없으면 새 폴더를 만들고 번호가 겹친다고 알린다. 앱은 번호로 템플릿을 구분하므로, 번호가 겹치면 가져올 때 다른 파일의 템플릿을 덮어쓴다.

## 2. 형식 (앱의 파서가 읽는 규칙)

````markdown
# STAGE 4 템플릿 — BFS / DFS / 그래프

> 이 STAGE를 왜 외우는지 한두 줄 (가져올 때 무시됨)

| # | 템플릿 | 목표 | 1회 | 2회 | 졸업 |
|---|---|---|---|---|---|
| T4-1 | BFS 격자 최단거리 | 3분 | | | ☐ |

---

## T4-1. BFS 격자 최단거리 (3분)

```cpp
// 백지에서 복원할 코드
```

> 방문 표시는 큐에 넣을 때. (요령·함정은 인용문으로 — 본문에 안 들어감)
````

| 규칙 | 이유 |
|---|---|
| 첫 제목은 `# STAGE {N} 템플릿 — {주제}` (가운데는 **긴 대시 —**) | `—` 뒤를 STAGE 이름으로 쓴다. `★` 뒤 메모는 버린다 |
| 템플릿 헤더는 `## T{N}-{번호}. {이름} ({목표 시간})` | 번호 뒤 **마침표**가 없으면 템플릿으로 인식하지 않는다 |
| 목표 시간은 `(30초)` `(1분)` `(1분 30초)` `(3분)` | 분·초가 든 첫 괄호를 읽는다. 없으면 1분이 된다 |
| 헤더 번호의 `{N}`은 파일 제목의 STAGE와 같게 | 앞 숫자가 곧 앱의 STAGE 묶음이다 |
| 템플릿 하나에 코드 블록 **하나** | 헤더부터 다음 `#`/`##` 전까지의 블록을 전부 이어 붙인다 |
| `###` 소제목 아래에 코드 블록을 두지 않는다 | `###`는 섹션을 끊지 않아서 앞 템플릿에 합쳐진다. 다른 개념이면 새 `##` |
| 설명은 코드 블록 밖 `>` 인용문으로 | 본문에 안 들어가므로 채점에 영향이 없다 |
| 템플릿이 아닌 `##` 섹션(예: `## 규칙`)에는 코드 블록을 넣지 않는다 | 형식이 안 맞아 버려지지만 사용자가 헷갈린다 |
| 번호는 1부터 차례대로, 중복 없이 | 앱은 번호로 같은 템플릿인지 판단한다. 중복되면 뒤의 것이 덮어쓴다 |

## 3. 내용 — 무엇을 템플릿으로 뽑나

좋은 템플릿은 **여러 문제에 그대로 다시 쓰는 뼈대**다. 문제 하나의 풀이가 아니다.

- **한 템플릿 = 한 개념**, 5~25줄. 더 길면 두 개로 쪼갠다. 백지 복원은 전부 맞아야 성공이라, 길수록 졸업이 어려워진다.
- **변수명은 짧고 관용적으로** (`n, m, dr, dc, vis, q, dist, adj`). 외울 글자 수가 줄고, 시험장에서도 같은 이름을 쓰게 된다.
- **문제마다 바뀌는 부분은 주석으로 표시**한다. 예: `if (maps[nr][nc] == 0) continue;  // 벽 (문제마다 다름)`
- **주석은 채점할 때 무시된다.** 그래서 "왜 이렇게 하는지"는 코드 주석으로 달아도 사용자 부담이 없다. 대신 주석에만 있는 핵심 로직이 있으면 안 된다.
- **쉬운 것 → 어려운 것 순서**로 4~7개. 뒤 템플릿이 앞 템플릿을 조립해서 쓰게 만들면 청킹이 쌓인다 (예: 격자 BFS → 연결요소 개수 = BFS 여러 번).
- 코드는 **컴파일되는 진짜 코드**로 쓴다.
- **코드 블록 맨 위에 그 코드가 쓰는 헤더를 템플릿마다 적는다.** 헤더도 외울 대상이다 — "이 STL엔 이 헤더"를 짝지어 익히게 한다.
  - 쓰는 것만: `vector`→`<vector>`, `queue`/`priority_queue`→`<queue>`, `sort`/`reverse`→`<algorithm>`, `isdigit`/`toupper`→`<cctype>`, `greater<>`→`<functional>` 식으로 표준상 필요한 헤더. `bits/stdc++.h`는 쓰지 않는다.
  - 순서: `#include`들 → `using namespace std;` → (필요하면 빈 줄 + `typedef pair<int, int> pii;` 같은 타입) → 빈 줄 → 본문
  - STL을 전혀 안 쓰는 코드(배열·반복문만)는 헤더 없이 둔다.
  - 앞 STAGE에 정의됐다고 생략하지 않는다 — 템플릿 하나만 복원해도 컴파일되게.
- **코드 모양은 앱 포맷(`Cmd+S`, 레포의 `.clang-format`)에 맞춘다.** 한 줄에 문장 하나, 한 줄 `if`/`for`도 몸통은 다음 줄, `&`는 이름 쪽(`vector<int> &v`). 직접 맞추기보다 검사기 `--fix`로 정리한다.

### 목표 시간

코드 블록의 줄 수(주석·빈 줄 포함, 검사기가 보여주는 숫자)로 먼저 정한다. 그다음 **알려진 함정**(off-by-one, 올림/내림, 오버플로, 방문 표시 시점처럼 틀리기 쉬운 한 줄)이 있으면 한 단계 올린다. 백지 복원은 한 글자만 틀려도 실패라서, 함정이 있는 템플릿은 확인할 시간이 더 필요하다.

| 코드 줄 수 | 목표 |
|---|---|
| 5줄 이하 | 30초 |
| 12줄 이하 | 1분 |
| 20줄 이하 | 2분 |
| 그 이상 | 3분 |

## 4. 쓰고 나서 검증

앱과 **같은 파서**로 읽어 본다. Scratchpad 레포 안이면:

```bash
node scripts/check-template.js --fix <템플릿.md 또는 학습 폴더>   # 코드 블록을 앱 포맷으로 정리 + 검사
node scripts/check-template.js <템플릿.md 또는 학습 폴더>         # 검사만
```

레포 밖에서 쓰고 있으면 Scratchpad 레포 경로로 실행한다 (예: `node ~/test/스크래치패드/scripts/check-template.js ~/woodie/study/coding-test`). 검사기를 쓸 수 없으면 2번 표를 한 줄씩 대조한다.

- 출력의 템플릿 개수와 목표 시간이 의도와 같은지 본다. (다른 폴더에서 실행하면 파일 경로가 `../../`로 길게 찍히는데, 동작에는 문제없다.)
- `⚠` 경고가 **0개**가 될 때까지 고친다. 경고는 "마침표 빠짐", "목표 시간 없음", "`###` 아래 코드 블록 합쳐짐", "STAGE 번호 불일치", "코드 블록 없음", "번호 중복", "코드 블록 안 닫힘", "앱 포맷과 다름"을 잡는다. 포맷 경고는 `--fix`로 없앤다 (clang-format이 없으면 포맷 검사는 건너뜀).

## 5. 끝나고 사용자에게 알려줄 것

- 만든 파일 경로와 템플릿 목록 (번호 · 이름 · 목표 시간)
- 앱에서 할 일: `Ctrl+T` → **레포에서 가져오기** → 새로 들어온 것 확인 → 가져오기
- 기존 템플릿의 본문을 고쳤다면 가져오기에서 "본문 바뀜"으로 뜨고, 본문만 바뀌고 시도 기록·앱에서 직접 정한 목표 시간은 남는다는 것
